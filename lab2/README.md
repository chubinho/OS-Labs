# Лабораторная работа 2 Вариант 3

Решение на C с двумя программами: родитель передаёт команды через канал, ребёнок делит целые числа и пишет результат в файл. Все файлы лабораторной находятся в папке `lab2/`.

## Запуск

Нужны компилятор C и Make. Из корня репозитория:

```sh
cd lab2
make
./build/parent
```

Пример ввода:

```text
results.txt
100 2 5
-7 2
```

В файле появятся строки `10` и `-3`. Ctrl+D на пустой строке завершает обычный ввод. Команда `10 0` завершает обе программы с кодом 2 без дополнительного ввода. Существующий файл результатов перезаписывается.

Путь к программе ребёнка можно передать явно: `./build/parent ./build/child`. Обычный запуск выполняется из папки `lab2/`; путь по умолчанию - `./build/child`.

## Устройство решения

1. `src/parent.c`: чтение имени файла, создание каналов, запуск ребёнка, обмен командами и ожидание завершения.
2. `src/child.c`: разбор одной команды в функции `calculate`, вычисление результата и запись в файл.
3. `src/common.c`: запись всех байтов, чтение ответа и закрытие дескриптора.
4. `src/common.h`: объявления общих функций и четыре ответа ребёнка.

Обмен устроен так:

```text
stdin -> parent -> pipe1 -> child -> файл
         parent <- pipe2 <- child
```

Ребёнок передаёт ответы одним байтом: `R` - готовность, `O` - успешная запись, `I` - неверная команда, `Z` - нулевой делитель. Родитель отправляет одну строку и ждёт ответ, прежде чем читать следующую.

В коде используются обычные условия, циклы и функции. `getline` читает строки произвольной длины, `strtok` выделяет числа, `strtol` проверяет их запись и диапазон. Метка `cleanup` собирает освобождение ресурсов в одном месте; при ошибке `goto cleanup` переводит выполнение к этому участку.

Отчёт по работе находится в [report.docx](report.docx). В папке `build/` после сборки появляются программы `parent` и `child`; эта папка и файлы `results*.txt` исключены из Git.

## Правила вычисления

Деление выполняется в типе `int` слева направо с усечением к нулю. Одно число возвращается без изменения. Пустая строка, неверный токен, число вне диапазона `int` и переполнение `INT_MIN / -1` отклоняют команду без записи результата. Сначала проверяется корректность всей строки; в корректной команде нулевой делитель имеет приоритет над арифметическим переполнением. Нулевой числитель допустим.

## Проверка работы

В [evidence/](evidence/) сохранены логи сборки и примеры запусков от 1 ноября 2026 года: обычное выполнение, неверный ввод, деление на ноль и трасса системных вызовов из Linux. В демонстрационных логах пути к выходным файлам приведены к относительным именам; команды, PID, результаты и коды завершения сохранены.

Повторная проверка выполнена 18 ноября 2026 года. В Ubuntu 24.04 arm64 прошли все 28 проверок и все 28 проверок с AddressSanitizer и UndefinedBehaviorSanitizer. На macOS arm64 прошли 27 проверок и тот же набор с санитайзерами; проверка записи в `/dev/full` пропущена как Linux-специфичная.

Полная сохранённая трасса - [evidence/strace-linux.log](evidence/strace-linux.log), выбранные системные вызовы - [evidence/strace-key-lines.log](evidence/strace-key-lines.log). В выводе программы показаны PID обоих процессов и результат ожидания ребёнка через `waitpid`.

В программе нет своего обработчика SIGINT/SIGTERM и наблюдения за ребёнком во время ожидания пользовательского ввода. Если ребёнок внешне убит в этот момент, родитель обнаружит разрыв при следующем обмене. Обычное завершение, ошибки обмена, открытие файла, нулевой делитель и ожидание ребёнка обработаны.
