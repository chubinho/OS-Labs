# Лабораторная работа 4 - вариант 3

Две программы на C для Linux. Родитель читает имя выходного файла первой строкой, затем команды с целыми числами. Ребёнок делит первое число на остальные слева направо и записывает по одному результату в файл. Данные передаются через файловое отображение `mmap`, уведомления - через `SIGUSR1` и `SIGUSR2`.

## Сборка и запуск

Нужны Linux, компилятор C и make. Из папки `lab4/`:

```sh
make
./build/parent
```

Пример ввода:

```text
results.txt
100 2 5
-7 2
42
```

В `results.txt` появятся `10`, `-3` и `42` на отдельных строках. Ctrl+D завершает ввод. Существующий выходной файл перезаписывается ребёнком. Путь к другой сборке ребёнка можно передать аргументом: `./build/parent ./build/child`.

```sh
printf 'results.txt\n100 2 5\n-7 2\n42\n' | ./build/parent
cat results.txt
make clean
```

## Правила обработки

- Числа имеют тип `int`; деление целочисленное, с усечением к нулю. Одно число сохраняется без изменения. Количество чисел ограничено доступной памятью и размером файла.
- Пустая команда, неверная запись числа, выход за диапазон `int`, встроенный нулевой байт и `INT_MIN / -1` отклоняют строку. Следующую команду можно вводить сразу.
- Ребёнок проверяет синтаксис всей строки. Для корректной строки нулевой делитель завершает обе программы с кодом 2; эта строка не записывается. Нулевой числитель допустим. Пример: `10 0` завершает работу, `0 2` даёт `0`.
- Обычное завершение возвращает 0, системная ошибка - 1, SIGINT/SIGTERM у родителя - 128 плюс номер сигнала. В диагностике выводятся PID обоих процессов.
- Родитель дожидается ребёнка через `waitpid`. Во время ожидания ввода проверяет его состояние; ребёнок замечает исчезновение родителя при ожидании следующей команды.
- Временный файл создаётся с правами 0600 и сразу удаляется из каталога. Унаследованный дескриптор сохраняет доступ после `exec`. Отображения и дескрипторы освобождаются при завершении. Каналы `pipe` не используются.

## Файлы

- `src/parent.c` - ввод, создание файла и ребёнка, передача команд, ожидание завершения.
- `src/child.c` - открытие выходного файла, получение команды, запись результата.
- `src/calculate.c` - проверка чисел и последовательное деление.
- `src/common.h`, `src/common.c` - формат сообщения, сигналы и освобождение ресурсов.
- `Makefile` - сборка двух программ в `build/`.
- `report.docx` - отчёт по шаблону с фрагментами кода и фактическими результатами.

## Диагностика в Linux

```sh
strace -f -o trace.log -e trace=process,memory,signal,openat,close,unlink,unlinkat,ftruncate ./build/parent
```

В трассе видны `ftruncate`, `mmap` с `MAP_SHARED`, запуск ребёнка, `kill`, `rt_sigtimedwait`, `munmap`, `close` и ожидание ребёнка. `trace.log` - результат вашего локального запуска; добавлять его в Git не требуется.
