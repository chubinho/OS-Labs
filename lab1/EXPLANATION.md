# Порядок разбора лабораторной

Программа состоит из родителя и ребёнка. У них два канала:

```text
пользователь -> parent -> команды -> child -> файл
               parent <- ответы  <- child
```

Сначала стоит понять обычный запуск, а затем прочитать проверки ошибок. В исходниках одна операция записана отдельным выражением; этапы идут в порядке выполнения.

## Родитель до запуска ребёнка

В начале `parent.c` объявлены переменные. `command_pipe` хранит два дескриптора канала команд, `response_pipe` — канала ответов. У каждого канала индекс 0 означает чтение, 1 — запись. Начальное значение -1 означает, что дескриптор ещё не получен или уже закрыт.

`line` — указатель на буфер для строки. Сначала он равен NULL. `getline` сама выделяет память и при необходимости увеличивает буфер. `line_capacity` хранит размер выделенного буфера, `line_length` — количество прочитанных байтов. В конце программы `free(line)` освобождает память.

Первый вызов `getline` получает имя файла. Родитель убирает перевод строки, проверяет имя и создаёт два канала через `pipe`.

## Запуск ребёнка

`fork` создаёт процесс. В родителе `child_pid` содержит PID ребёнка; в ребёнке это значение равно 0. Поэтому `if (child_pid == 0)` выполняется только в ребёнке.

В этой ветке `dup2` подключает чтение канала команд к `STDIN_FILENO` и запись канала ответов к `STDOUT_FILENO`. Исходные дескрипторы каналов после этого закрываются. Далее `execl` запускает отдельную программу child, передавая ей имя файла аргументом. PID при exec сохраняется.

При успехе `execl` не возвращается: вместо прежнего кода начинает работать `main` из `child.c`. При ошибке печатается сообщение, а ребёнок завершает работу через `_exit(1)`.

## Обмен одной командой

Родитель закрывает ненужные ему концы каналов и ждёт ответ READY. Он означает, что ребёнок запустился и открыл файл.

Дальше работает обычный цикл `while (1)`:

1. Прочитать строку пользователя через `getline`. На конце ввода выйти из цикла.
2. Отправить строку ребёнку через `write_all`.
3. Прочитать один ответ через `read_status`.
4. При ZERO завершить работу; при DONE или INVALID перейти к следующей строке.

Родитель ждёт ответ до нового чтения пользовательского ввода. Поэтому нулевой делитель завершает его без дополнительного Enter. Математические вычисления выполняет только ребёнок.

| Ответ | Байт | Значение |
| --- | --- | --- |
| READY | R | Файл открыт, ребёнок готов |
| DONE | O | Результат записан |
| INVALID | I | Команда отклонена |
| ZERO | Z | Нулевой делитель, завершение |

`enum` в common.h даёт этим байтам понятные имена. По каналу передаётся один байт, а не текстовое название.

## Вычисление в ребёнке

В `main` из `child.c` файл открывается через `open`, после чего ребёнок отправляет READY. Затем цикл читает команды через `getline` и вызывает `calculate` для каждой строки. Проверенный результат записывается через `dprintf`, после записи родителю отправляется DONE. Ошибки ввода и вывода проверяются.

В функции `calculate`:

- `strtok` выделяет части строки между пробельными символами. Например, из `100 2 5` по очереди получаются строки `100`, `2`, `5`.
- `strtol` переводит очередную часть в число. `number_end` позволяет проверить, что число занимает всю часть: `12x` будет отклонено. Дополнительно проверяется диапазон int.
- `is_first_number` равен 1, пока не найдено первое число. Оно становится начальным результатом `answer`.
- Следующие числа становятся делителями. Пример: 100 / 2 = 50, затем 50 / 5 = 10.

`answer` передаётся через указатель: запись `*answer = ...` меняет результат у вызывающей функции. Сама `calculate` возвращает ответ DONE, INVALID или ZERO.

Два флага нужны для проверки всей строки. `has_zero_divisor` запоминает нулевой делитель, `has_overflow` — случай INT_MIN / -1. После них деление прекращается, но оставшиеся части строки продолжают проверяться. Так программа не выполняет опасную операцию и не записывает частичный результат.

Примеры правил: `8 0 garbage` отклоняется как неверная команда; `-2147483648 -1 0` для 32-битного int завершает работу из-за нуля. Обычное деление int усекает результат к нулю: `-7 2` даёт -3. Первый ноль допустим: `0 5` даёт 0.

## Общие функции и завершение

`write_all` вызывает `write` в цикле: одна запись может передать только часть данных. После каждого успешного вызова сдвигается указатель на ещё не отправленные байты. `read_status` читает один байт ответа. Если системный вызов прерван сигналом с ошибкой EINTR, эти функции повторяют попытку.

`close_fd` закрывает дескриптор и устанавливает его значение в -1. Функция получает адрес переменной, чтобы изменить её у вызывающего кода. Повторный вызов с -1 ничего не делает.

У каждого `main` есть метка `cleanup`. `goto cleanup` означает «перейти к общему завершению». Там освобождается строка и закрываются открытые ресурсы. У родителя также вызывается `waitpid`, чтобы дождаться ребёнка и получить его код завершения.

На обычном конце ввода родитель закрывает канал команд, ребёнок получает конец ввода и выходит. При нулевом делителе ребёнок отправляет ZERO и выходит с кодом 2; родитель тоже возвращает 2. При собственной ошибке родитель закрывает каналы, посылает ребёнку SIGTERM и вызывает `waitpid`. Код 0 означает обычное завершение, код 1 — ошибку.

Своих обработчиков SIGINT/SIGTERM и наблюдения за ребёнком во время ожидания пользовательского ввода здесь нет. Если ребёнок внешне завершён в этот момент, родитель обнаружит разрыв при следующем обмене. При нулевом делителе ответ приходит сразу, поэтому программа завершается без нового ввода.

## Трассировка в Linux

```sh
make -B CC=gcc
strace -f -tt -yy ./build/parent
```

В трассе нужно найти создание каналов, создание ребёнка, dup2, execve, открытие файла, передачу строки, запись результата и ожидание ребёнка. Имена могут отличаться от функций libc: open может вызывать openat, fork — clone, waitpid — wait4. 1 ноября 2026 года трассировка выполнена в Ubuntu 24.04 arm64; результаты сохранены в evidence/strace-linux.log. В этом запуске fork, pipe, dup2 и waitpid представлены в ядре как clone, pipe2, dup3 и wait4.

В учебнике курса нужны разделы 1.4, 2.1 и 2.2: Таненбаум и Вудхалл, «Операционные системы. Разработка и реализация», третье издание. Справка по системным вызовам: [pipe](https://man7.org/linux/man-pages/man7/pipe.7.html), [exec](https://man7.org/linux/man-pages/man2/execve.2.html), [wait](https://man7.org/linux/man-pages/man2/waitpid.2.html).
