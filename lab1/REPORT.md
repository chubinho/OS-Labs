## 1. Цель работы

Разработать на языке C две отдельные программы и организовать обмен между родительским и дочерним процессами через каналы POSIX. Для варианта 3 дочерний процесс должен последовательно делить первое целое число строки на остальные и записывать результат в файл. При нулевом делителе оба процесса должны завершать работу.

## 2. Краткое описание архитектуры решения

Программа parent получает имя выходного файла первой строкой, создаёт два канала и запускает child с помощью fork и execl. Имя файла передаётся ребёнку аргументом. Ветка дочернего процесса перенаправляет чтение первого канала в стандартный ввод, а запись второго — в стандартный вывод с помощью dup2.

Родитель отправляет одну команду и ждёт ответ. Ребёнок открывает файл, проверяет числа типа int, выполняет деление слева направо и записывает результат. Ответы передаются одним байтом: R — готовность, O — успешная запись, I — отклонённая команда, Z — нулевой делитель. Диагностика с PID выводится отдельно в stderr.

Файлы parent.c и child.c содержат логику процессов, common.c и common.h — общие операции чтения, записи и закрытия дескрипторов. Строки произвольной длины читаются через getline. Ошибки системных вызовов проверяются; память и дескрипторы освобождаются, родитель получает завершение ребёнка через waitpid.

### 2.1 Схема взаимодействия компонентов

```text
stdin -> parent -> pipe1 -> child -> файл
         parent <- pipe2 <- child
```

Рисунок 1 — Обмен между процессами

После ответа Z родитель прекращает ввод без дополнительного Enter. При обычном конце ввода он закрывает канал команд; ребёнок получает EOF и завершает работу. Ненужные концы каналов закрыты в обоих процессах.

## 3. Листинг ключевых фрагментов кода

Ниже приведены фрагменты текущих исходников. Полный код находится в каталоге src локального Git-репозитория лабораторной работы.

### 3.1 Создание каналов и процесса

Два канала создаются до fork, чтобы ребёнок унаследовал их дескрипторы. При ошибке выполняется переход к освобождению ресурсов.

```c
if (pipe(command_pipe) == -1) {
    perror("pipe");
    goto cleanup;
}

if (pipe(response_pipe) == -1) {
    perror("pipe");
    goto cleanup;
}

child_pid = fork();
if (child_pid == -1) {
    perror("fork");
    goto cleanup;
}
```

Листинг 1 — Создание каналов и дочернего процесса

### 3.2 Перенаправление потоков и запуск child

Следующий фрагмент выполняется в ветке ребёнка. Стандартный ввод подключается к каналу команд, стандартный вывод — к каналу ответов.

```c
if (dup2(command_pipe[0], STDIN_FILENO) == -1) {
    perror("dup2 stdin");
    _exit(1);
}

if (dup2(response_pipe[1], STDOUT_FILENO) == -1) {
    perror("dup2 stdout");
    _exit(1);
}
```

Листинг 2 — Перенаправление стандартных потоков

После закрытия исходных дескрипторов вызывается execl. При успешном запуске прежняя программа заменяется на child; строка line содержит имя файла.

```c
execl(child_program, "child", line, (char *)NULL);

perror("execl");
_exit(1);
```

Листинг 3 — Запуск отдельной программы ребёнка

### 3.3 Вычисление и завершение

Первое число становится начальным результатом. Для последующих чисел проверяются ноль и переполнение INT_MIN / -1. Разбор оставшихся токенов продолжается, чтобы неверная строка отклонялась целиком.

```c
if (is_first_number == 1) {
    *answer = (int)number;
    is_first_number = 0;
} else if (number == 0) {
    has_zero_divisor = 1;
} else if (has_zero_divisor == 0 && has_overflow == 0) {

    if (*answer == INT_MIN && number == -1) {
        has_overflow = 1;
    } else {
        *answer = *answer / (int)number;
    }
}
```

Листинг 4 — Последовательное целочисленное деление

Результат записывается только после проверки всей строки. При нулевом делителе ребёнок отправляет Z и завершает работу с кодом 2; родитель принимает этот ответ и также возвращает 2.

```c
response = read_status(response_pipe[0]);
if (response == ZERO) {
    exit_code = 2;
    break;
}
```

Листинг 5 — Остановка родителя при нулевом делителе

При завершении родитель закрывает каналы и вызывает waitpid. Прерванное ожидание повторяется при EINTR. Это позволяет получить код ребёнка и не оставить зомби-процесс.

```c
while (1) {
    waited_pid = waitpid(child_pid, &child_status, 0);
    if (waited_pid == -1 && errno == EINTR) {
        continue;
    }
    break;
}
```

## 4. Результаты работы

Проверки выполнены 1 ноября 2026 года. На macOS arm64 программа собрана Apple Clang с параметрами -std=c11 -Wall -Wextra -Wpedantic -Werror. Дополнительно программа собрана и проверена в контейнере Ubuntu 24.04 arm64 с GCC 13.3.0. Проверены обычные вычисления, неверный ввод, ошибки файлов и каналов, а также завершение обоих процессов при делении на ноль.

Для запуска из каталога проекта используются команды make и ./build/parent. В примерах ниже после имени файла введены команды; показаны фрагменты фактических логов с PID и полученное содержимое файла.

### 4.1 Обычное выполнение

Введены строки: 100 2 5; -7 2; 5 2 2. После окончания ввода получены результаты 10, -3 и 1; код завершения равен 0.

```text
[parent pid=94729] created child=94730
[child pid=94730] line=1: result=10
[child pid=94730] line=2: result=-3
[child pid=94730] line=3: result=1
[parent pid=94729] waitpid reaped child=94730 exit=0
```

Разные PID подтверждают наличие двух процессов. Вычисления выполняются ребёнком, а строка waitpid reaped подтверждает, что родитель получил его завершение.

### 4.2 Деление на ноль и ошибочный ввод

Для команд 100 2; 9 0; 8 2 в файл записано только 50. При обработке второй строки оба процесса завершились с кодом 2; третья команда не вычислялась.

```text
[parent pid=94731] created child=94732
[child pid=94732] line=1: result=50
[child pid=94732] line=2: division by zero
[parent pid=94731] waitpid reaped child=94732 exit=2
```

Лог 1 — Завершение при нулевом делителе

Строки 12x 2 и -2147483648 -1 отклонены. После них корректная команда 8 2 обработана, в файл записано 4, код завершения равен 0.
