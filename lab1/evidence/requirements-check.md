# Проверка лабораторной 2 — вариант 3

Дата выполнения проверок: **1 ноября 2026 года**.

Основание: «Лабораторная работа 2.pdf», физические страницы 1, 2 и 11; «Требования к выполнению лабораторных работ.docx». Вариант 3 относится к первой группе.

| Требование | Реализация и наблюдаемое подтверждение |
| --- | --- |
| Язык C | Четыре файла .c/.h; сборка C11 без предупреждений при -Wall -Wextra -Wpedantic -Werror |
| Отдельные родитель и ребёнок | Два исполняемых файла parent и child; fork и execl; разные PID в логах, execve child в strace |
| Первая строка — имя файла | Родитель читает имя до fork; передаёт его аргументом execl; проверено имя с пробелами и неверное/пустое имя |
| Первый канал соединён со stdin ребёнка | pipe до fork, затем dup2(command_pipe[0], STDIN_FILENO); в Linux arm64 виден dup3 на fd 0 |
| Обратный канал | Второй pipe, stdout ребёнка перенаправлен на запись ответа; статусы R/O/I/Z подтверждаются обменом в трассе |
| Деление первого int на последующие | Функция calculate находится в child.c; проверены последовательность, отрицательные числа, усечение, границы int и один аргумент |
| Произвольное количество чисел | getline и последовательный strtok/strtol без массива фиксированного размера; обработана строка с 150001 делителем |
| Проверка нуля в ребёнке | В child.c номер делителя проверяется до арифметики; ZERO передаётся родителю |
| При нуле завершаются оба процесса | Оба возвращают 2; проверка с открытым stdin подтвердила завершение родителя и отсутствие PID ребёнка; последующие команды не выполняются |
| Ребёнок создаёт файл и пишет результаты | open с O_CREAT/O_TRUNC, dprintf в child; в трассе открытие и write результата делает PID ребёнка |
| Обработка ошибок | Проверены неверные числа, переполнение, отсутствие программы ребёнка, ошибки файла, разрыв канала и нехватка дескрипторов |
| Завершение и ресурсы | Закрытие ненужных концов, free, close, waitpid с EINTR; проверены обычное завершение и остановка при нуле; ASan/UBSan не выявили ошибок |
| Модульность и сборка | parent.c, child.c, common.c/common.h и Makefile; нативный POSIX API |
| Наглядное подтверждение и профиль вызовов | Реальные логи с PID, strace -f -tt -yy, ключевые вызовы и отчёт по предоставленному шаблону |
| Работа в Linux | Проверена в контейнере Ubuntu 24.04 arm64, GCC 13.3.0, glibc 2.39; контейнер использовал Linux-ядро Docker Desktop |

## Фактический результат

- На macOS arm64 и в Ubuntu 24.04 проверены вычисления, неверный ввод, ошибки файла и каналов, завершение при нулевом делителе. ASan/UBSan не выявили ошибок.
- Трасса отдельного запуска: 100 2 5 даёт 10; затем 9 0 завершает оба процесса с кодом 2; команда 8 2 не выполняется.
- Из исходников удалены 23 комментария. Исполняемый текст после удаления пробельных символов совпал с текстом до изменения без комментариев. Логика программы не переписывалась.

## Границы проверки

Выполненные прогоны подтверждают перечисленные сценарии, а не все возможные внешние воздействия. В программе нет пользовательских обработчиков SIGINT/SIGTERM и слежения за ребёнком во время ожидания пользовательского ввода. При внешнем завершении ребёнка в этот момент разрыв обнаруживается при следующем обмене. Требуемое завершение при нуле с открытым вводом проверено отдельно.

Устное понимание кода и возможность самостоятельно изменить его на защите этими проверками не оцениваются. Фактическая дата проверок — 1 ноября 2026 года.
